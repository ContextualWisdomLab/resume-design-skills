## 적용 범위와 우선순위

제출처 규정 → 원본과 사용자 요구 → 아래 D2 순서로 적용한다. D2의 수치·색·열 비율은 이 프로젝트의 디자인 기본값이다. 한국 테크 기업이나 Microsoft의 공식 이력서 규격으로 표현하지 않는다. 출처 ID는 [출처 장부](sources.md)를 가리킨다.

비교할 수 있는 경력·자격·지표처럼 반복되는 항목에 표를 사용한다. 자유 형식 이력서 전체, 연락처와 본문을 좌우로 나누는 배치, 긴 자기소개를 넣는 상자는 표로 만들지 않는다. 긴 프로젝트 설명은 제목·문단·목록으로 작성한다. 지정 양식의 필수 표에는 보존 경로를 적용한다.

S4를 참고해 새 표에는 단순한 행·열과 명확한 열 머리글을 사용한다. 새 표에 장식용 병합, 셀 안의 표, 빈 행·열을 넣지 않는다. 기존 회사 양식의 병합이나 필수 공란은 그대로 보존한다. 표가 있다는 이유만으로 ATS 실패를 판정하지 않는다(S3).

## 공통 규격 D2

| 항목 | 기본값 | 적용 규칙 |
| --- | --- | --- |
| 표 위치 | 본문 흐름 안, 왼쪽 기준선에 정렬 | 떠 있는 표·텍스트 둘러싸기·공백 정렬을 사용하지 않음 |
| 전체 너비 | 현재 본문 가용 폭의 100% | 용지 폭에서 좌우 여백·현재 들여쓰기를 뺀 값. 원본의 지정 폭이 있으면 유지 |
| 열 너비 | 아래 목적별 비율 | 합계 100%. 종이 크기가 달라지면 다시 계산하고 렌더 |
| 한글 본문 | Pretendard Regular 11 pt | 영문·숫자도 같은 계열. 회사 지정 글꼴 우선 |
| 머리행 | Pretendard SemiBold 11 pt | `Pretendard SemiBold` 패밀리를 사용하고 Bold를 중복 적용하지 않음 |
| 본문·머리행 글자색 | `#000000` | 링크·값의 의미를 색만으로 전달하지 않음 |
| 머리행 바탕 | `#F2F4F6` | 검정 글자와 조합. 같은 문서의 표에 동일 적용 |
| 본문 바탕 | `#FFFFFF` | 기본형에는 교대 음영·강조색 셀을 추가하지 않음 |
| 테두리 | 모든 바깥선·안쪽선 0.5 pt, `#D9D9D9` | 이중선·두꺼운 외곽선 없음. 원본 지정 선이 있으면 유지 |
| 셀 좌우 여백 | 각각 3 mm | 셀 내부 문단 들여쓰기는 0. 표 전체 너비에 포함 |
| 셀 위아래 여백 | 각각 2 mm | 행 높이를 고정하지 않고 내용에 따라 늘어남 |
| 셀 줄 간격 | 1.15배 | `정확히` 줄 간격으로 글자를 자르지 않음 |
| 셀 문단 간격 | 앞 0 pt, 뒤 0 pt | 한 셀에 여러 문단이 꼭 필요하면 문단 사이 2 pt |
| 표 제목 | 실제 제목 스타일, SemiBold 11~12 pt | 표 앞 10 pt, 제목 뒤 4 pt. 표의 첫 행과 함께 유지 |
| 표 다음 내용 | 앞 간격 6 pt | 다음 섹션의 앞 간격과 중복해 과도한 공백을 만들지 않음 |
| 행 높이 | 자동 | 읽을 수 있는 최소 높이는 여백과 줄 간격으로 확보. `정확히` 금지 |

표 폭은 셀 안의 여백까지 포함한다. 예를 들어 A4·좌우 20 mm 여백이면 가용 폭은 170 mm, Letter·같은 여백이면 175.9 mm다. 이 예는 용지 선택 의무가 아니다. 아주 짧은 비교표는 가용 폭보다 작게 만들 수 있으나 표마다 기준선을 임의로 바꾸지 않는다.

표 안의 항목명·회사·직책도 기본은 Regular 11 pt다. 열 이름이 있는 머리행만 SemiBold로 구분한다. 표 밖 회사·직책 소제목의 SemiBold 규칙을 모든 본문 셀에 일괄 적용하지 않는다.

Word에서는 상대 너비나 창 너비 맞춤을 우선 검토한다. 인쇄·PDF용으로 열 폭을 고정할 때에도 현재 페이지 안에서 계산하고 다른 용지·모바일 화면에 동일한 mm 값을 강제하지 않는다. S4의 고정 폭 표에 대한 주의와 모바일·확대 사용성 확인은 별도로 남긴다. 이 규격만으로 접근성을 보장하지 않는다.

## 목적별 열 구성

| 유형 | 열 순서 | 너비 비율 | 사용 범위 |
| --- | --- | --- | --- |
| A 항목과 값 | 항목 / 내용 | 22% / 78% | 짧은 경력 요약, 자격 등 반복되는 항목·값. 긴 서술문 전체를 넣지 않음 |
| B 경력 요약 | 기간 / 회사·직책 / 담당 범위 | 24% / 28% / 48% | 경력을 빠르게 비교하는 요약. 자세한 문제·행동·결과는 아래 본문에 배치 |
| C 성과 비교 | 지표·조건 / 개선 전 / 개선 후 / 변화 | 46% / 18% / 18% / 18% | 같은 측정 조건의 수치 비교. 단위·기간·분모와 본인 기여를 가까이 유지 |

위 비율을 시작값으로 적용하고 가장 긴 실제 항목으로 확인한다. 2열은 주로 항목·값, 3열은 짧은 반복 기록, 4열은 짧은 수치 비교에 쓴다. 새 표가 5열 이상 필요하면 항목을 줄이거나 표와 본문으로 목적을 나눈다. 회사가 지정한 열 수에는 이 제한을 적용하지 않는다.

긴 회사명·직책 때문에 3열이 좁으면 설명 열을 재배분하거나 해당 경력을 문단으로 전환한다. 글자를 한 글자씩 세로로 밀어 넣거나 8~9 pt로 축소하지 않는다. 서로 다른 표를 나누는 경우 제목에 각각의 범위를 쓰고 하나의 기록을 이중 집계하지 않는다.

## 정렬과 문장 처리

| 셀 내용 | 가로 정렬 | 세로 정렬 |
| --- | --- | --- |
| 항목명·회사명·역할·문장 | 왼쪽 | 짧은 1~3줄 행은 가운데 |
| 기간·날짜·짧은 상태 | 가운데 | 가운데 |
| 비교하는 수치와 단위 | 오른쪽 | 가운데 |
| 머리행 | 해당 본문 열의 정렬과 일치 | 가운데 |
| 여러 문단으로 긴 설명을 담는 필수 행 | 왼쪽, 수치 열은 기존 규칙 유지 | 같은 행의 셀을 위쪽에 맞춰 시작점 정리 |

날짜 열에는 `YYYY.MM`처럼 일관된 표기를 사용하되 원문의 날짜 정밀도를 늘리지 않는다. 기간이 두 줄이면 시작·끝의 경계에서 나누고, 종료되지 않은 역할의 `현재`를 보존한다. 숫자는 단위·소수 자릿수·증감 기호를 일정하게 표시하며 의미가 다른 `%`와 `%p`를 바꾸지 않는다.

칸이 좁을 때에는 자연스러운 줄바꿈 → 열 폭 조정 → 상세 설명의 본문 이동 순서로 고친다. 헤더 줄바꿈이나 약칭은 뜻을 보존할 때만 사용한다. 부득이한 보조 정보는 10~10.5 pt까지 검토하되 본문 기본 11 pt를 유지하고 전체 표를 축소하지 않는다. 내용 편집 권한이 없으면 문장 삭제·요약 대신 구조 조정안을 제시한다.

미확인·해당 없음·의도된 공란을 구분한다. 새 표의 값은 확인된 상태만 표시한다. 원본의 빈칸을 추정 값이나 대시로 일괄 채우지 않는다. 표 밖 설명에 팀 성과와 개인 기여, 수치의 측정 조건을 연결한다.

## 페이지 나눔

1. **실제 머리행을 지정한다.** 첫 행에 열 이름을 쓰고 Word의 머리행과 반복 머리행 설정을 사용한다. 진한 글씨·회색 바탕만으로 머리글 의미를 대신하지 않는다.
2. **자동 페이지 흐름을 사용한다.** 여러 쪽에 걸친 표의 첫 머리행을 반복한다. 표 내부에 수동 페이지 나누기를 넣지 않는다. Word는 수동 나누기에서 머리행을 반복하지 않을 수 있다(S13).
3. **짧은 행은 함께 둔다.** 한 페이지 안에 충분히 들어가는 짧은 행에는 페이지 사이 행 나눔을 막는다. 표 전체의 모든 문단을 `다음 문단과 함께`로 묶지 않는다.
4. **긴 필수 행은 나눈다.** 한 페이지보다 긴 설명 행은 행 나눔을 허용하고 셀 문단의 과도한 `문단 보호`·`다음 문단과 함께`를 해제한다. 새 자유 형식 표라면 긴 설명을 먼저 본문으로 옮긴다. 내용 잘림을 빈 공간보다 먼저 해결한다.
5. **제목과 머리행을 고립시키지 않는다.** 표 제목·머리행·첫 데이터 행이 함께 보이게 한다. 데이터 행끼리는 필요한 경우 자연스럽게 나누며 모든 행을 연쇄 연결하지 않는다.
6. **이어지는 쪽을 읽는다.** 반복된 열 이름, 동일한 열 순서·폭, 행의 시작과 끝, 페이지 아래의 잘림을 확인한다. 필요한 계속 표시가 허용된 양식인지 먼저 확인한다.

머리행 반복, 행 나눔 허용, 행 높이 자동은 서로 다른 설정이다. 어느 하나만으로 나머지를 확인했다고 기록하지 않는다. 실제 Word와 변환기의 결과가 다를 수 있으므로 최종 제출 파일로 검수한다.

## 회사 지정 양식

[지정 양식 보존](employer-forms.md)을 먼저 적용한다. 표 수, 행·열 수, 병합 범위, 항목 이름과 값의 대응, 서명·사진·동의 영역을 대조 기준으로 기록한다. D2를 맞추려고 병합을 풀거나 열을 줄이거나 필수 공란을 채우지 않는다.

허용된 서식만 정리한다. 서체·셀 여백·줄 간격·선·음영을 바꿀 수 있는지 원본 지시를 확인한다. 행 높이·쪽수·서체가 고정돼 내용이 잘리면 사실을 삭제하지 말고 충돌을 설명한다. 표 개수와 텍스트 총량이 같다는 것만으로 구조가 보존됐다고 판단하지 않는다.

## 제작과 검수

- 제목·문장·숫자를 편집 가능한 텍스트로 만든다. 표를 이미지로 붙이지 않는다.
- 생성 코드에서는 표 전체 폭, 열 그리드, 셀의 선호 폭이 같은 비율을 표현하게 한다. 셀 여백·테두리·음영·정렬을 명시하고 테마 기본값에 맡기지 않는다.
- 머리행·반복 머리행, 짧은 행의 나눔 방지, 긴 행의 나눔 허용을 각각 확인한다. 원본 병합을 복제할 때는 셀 값의 대응도 검사한다.
- 최종 DOCX를 렌더해 모든 페이지의 잘림·여백·줄바꿈·행 경계와 표 다음 간격을 확인한다. 한글·영문·숫자 혼용과 긴 회사명으로 확인한다.
- PDF의 기본·배치 모드 추출을 비교한다. 행마다 기간·회사·역할·수치의 대응을 다시 확인한다. 모든 글자가 있다는 사실과 올바른 읽기 순서를 구분한다.
- 기본 추출에서 열이 따로 모이거나 행 순서가 섞이면 그 결과를 기록한다. 선형 읽기가 필요한 자유 형식 제출본은 문단·목록 구성을 검토하고 다시 확인한다. 필수 회사 표는 보존하면서 셀별 원문 대조와 가능한 제출 시스템 미리보기를 확인한다. 배치 모드만 맞는 결과를 일반 읽기 순서 통과로 보고하지 않는다.
- `audit_docx.py`의 표 경고는 수동 검수 대상으로 처리한다. 이 도구는 열 너비·병합 관계·머리행 반복·시각적 잘림을 판정하지 않는다.
- 공개 예제는 합성 자료만 사용한다. 실제 회사 양식, ATS 업로드, Word 네이티브 화면, 스크린리더를 확인하지 않았다면 미실시로 남긴다.

`scripts/build_examples.py`가 생성하는 표 예제는 A·B·C의 시각적 적용을 보여 준다. 이 예제의 PDF는 기본 텍스트 추출에서 일부 열의 순서가 달라지므로 선형 읽기 순서가 검증된 제출 템플릿으로 표현하지 않는다. 실제 지원서에 예제의 회사·기간·수치를 복사하지 않는다. [검수 절차](verification.md)와 함께 사용한다.
