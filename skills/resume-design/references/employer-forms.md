# 회사 지정 양식 보존

## 처음에 기록할 구조

원본과 지시를 함께 확인한다. 회사가 제공한 현재 4쪽이라는 사실만으로 4쪽이 의무라고 확정하지 않는다. 의무 여부를 확인하기 전에는 기존 구조를 보존하며 가능한 서식 정리를 진행한다.

| 고정 요소 | 기록할 내용 |
| --- | --- |
| 문서 규격 | 용지·방향·여백·의무 쪽수·파일 형식 |
| 필수 항목 | 항목명, 입력값, 비워 두도록 지정된 필드 |
| 표 | 표 개수, 행·열, 병합 관계, 항목과 값의 연결 |
| 페이지 | 고정 시작 항목, 서명·동의·사진 영역 |
| 표현과 값 | 회사명, 직급, 역할, 날짜, 학력, 숫자·단위·조건 |
| 편집 허용 범위 | 서체·여백·행 높이·줄바꿈·항목 이동의 허용 여부 |

일반 이력서의 단일 열 원칙을 적용하려고 지정 표를 제거하지 않는다. 사진란·동의문을 미국 대학의 일반 이력서 조언만으로 없애지 않는다. 필수 공란에 임의 값을 채우지 않는다.

## 안전한 서식 조정

허용된 표 서식의 구체적인 수치는 [표 디자인 규격 D2](table-design.md)를 따른다. 원본의 고정 폭·선·음영·서체·병합 지시가 D2보다 우선한다. 행·열 구조를 바꾸지 않는 작업이라도 항목과 값의 대응은 전후 대조한다.

허용 범위 안에서 같은 역할의 텍스트를 같은 스타일로 정리한다. 표의 셀 여백, 들여쓰기, 줄 간격, 선의 강도를 일관되게 조정한다. 여러 줄 설명에는 행 높이 `정확히`를 사용하지 않는다. 회사가 행 높이를 고정했다면 내용을 자르지 말고 실제 충돌을 알린다.

짧은 개인정보 행과 짧은 경력 묶음은 페이지 사이에서 갈라지지 않게 한다. 한 페이지보다 긴 설명 행은 나눌 수 있어야 한다. 모든 행에 일괄적으로 행 나눔 금지를 적용하지 않는다. 반복되는 표 제목이 있다면 다음 쪽에서도 열의 의미를 알 수 있게 한다.

다단·병합 셀 때문에 자동 추출이 흔들리는 경우 지정 양식은 보존한다. 셀별 값과 관계를 직접 대조하고, 제출 시스템의 실제 미리보기·자동 입력값을 확인할 수 있을 때 확인한다. 별도 자유 형식본은 제출처가 허용하거나 사용자가 요구했을 때만 만든다.

## 지정 양식 전후 대조

1. 표·행열·병합·항목 순서를 대조한다. `audit_docx.py`는 표 개수를 알려 주지만 구조 전체의 보존까지 증명하지 않는다.
2. 각 항목 이름과 값의 연결을 확인한다. 텍스트 전체가 같아도 다른 셀로 옮겨졌으면 의미가 달라질 수 있다.
3. 실제 모든 페이지에서 표 경계, 긴 회사명, 날짜, 서명·사진 영역을 확인한다.
4. PDF에서도 같은 항목과 값을 확인하고 텍스트 추출 순서를 읽는다.
5. 제출 시스템 미리보기나 재다운로드 검사를 하지 못했으면 미실시로 기록한다. 지원서 제출은 별도 사용자 요청 없이 수행하지 않는다.
