# 이력서 디자인 규칙

## 원칙과 적용 순서

제출처 규정 → 제공된 원본과 사용자 요구 → 이 문서의 기본값 순서로 적용한다. 수치는 이 프로젝트의 편집 기본값(D1)이며, 채용 효과가 검증된 최적값이 아니다. 출처 번호는 `sources.md`를 가리킨다.

Harvard의 일관된 배열·여백·역순 경력 권고(S1), Greenhouse의 파싱 위험 안내(S3), Microsoft의 문서 구조 지침(S4)을 참고한다. 규칙을 적용한 뒤에도 실제 렌더와 텍스트 순서를 확인한다.

## 기본 디자인 수치 D1

| 요소 | 시작값 | 조정 기준 |
| --- | --- | --- |
| 용지 | 제출처·원본 규격 유지; 미지정이면 지역과 사용처에 맞는 A4 또는 Letter를 명시 | 용지 변경 뒤 반드시 재렌더 |
| 여백 | 사방 18~22 mm | 회사 양식이 우선; 부족한 페이지를 여백 축소만으로 해결하지 않음 |
| 본문 | 11 pt, 보통 굵기 | 글꼴의 실제 크기·한글 가독성을 확인; 지속 본문을 10 pt 아래로 축소하지 않음 |
| 이름 | 20~24 pt, 굵게 | 긴 이름은 균형 있게 줄바꿈; 과도한 자간 없음 |
| 섹션 제목 | 12~14 pt, 굵게 | 같은 단계는 같은 스타일 |
| 회사·직책 | 11~12 pt, 굵게 | 날짜와 관계가 명확하게 보이도록 배치 |
| 보조 정보 | 10~11 pt | 날짜·연락처를 희미하거나 작게 만들지 않음 |
| 줄 간격 | 1.10~1.20배 | 한글·영문·기호의 상하 잘림을 확인; 고정 높이로 강제하지 않음 |
| 본문 문단 뒤 | 3~5 pt | 같은 수준의 항목에 동일 적용 |

| 본문·제목 색 | 검정 또는 충분히 진한 중립색 | 흑백에서도 위계가 유지되어야 함 |
| 배경 | 흰색 | 큰 색 면과 사진 배경을 기본으로 사용하지 않음 |

S2는 10~12 pt와 최소 0.5 inch 여백을 안내한다. 위 수치 범위는 그 권고를 복제한 규격이 아니라 한글 혼용 문서의 작업 시작값이다. 단일 서체 계열에서 본문·소제목·이름의 굵기를 제한하고 색·선·크기 중 여러 강조를 한꺼번에 겹치지 않는다.

디지털 본문 색 대비는 S7의 일반 텍스트 기준인 4.5:1을 참고 목표로 삼는다. 이것만으로 Word·PDF 접근성이나 WCAG 전체 적합성을 주장하지 않는다. 색 외에도 제목·굵기·문단 순서가 관계를 전달해야 한다.

## 세 가지 프로필

| 프로필 | 상단 배치 | 본문 구성 | 페이지 운영 |
| --- | --- | --- | --- |
| 기본형 | 이름·연락처 → 짧은 직무 요약 | 관련 경력 → 학력·자격·기술 | 한 쪽 예제에서 시작하되 제출 조건·필요 정보로 결정 |
| 경력자형 | 이름·연락처 → 전문 영역과 확인된 책임 범위 | 최근 핵심 경력 → 이전 관련 경력 → 필요한 자격·기술 | 두 쪽 예제로 구조를 보여 주되 고정 상한으로 삼지 않음 |
| 지정 양식형 | 기존 위치 유지 | 항목·표·필드 관계 유지 | 기존 쪽수와 의무 쪽수를 구분; `employer-forms.md` 적용 |

신입은 교육·프로젝트가 앞에 올 수 있다. 학술 CV는 연구·출판·교육 등의 목적과 제출 규정을 따른다. 경력이 긴 지원자의 초기 실무나 리딩 경험이 자격 판단에 필요하면 남긴다. 경력을 최근 몇 년으로 기계적으로 자르지 않는다.

## 경력 한 건의 단위

회사명, 직책·소속, 기간을 먼저 읽고 그 아래에서 책임·행동·결과를 읽을 수 있게 한다. 동일 회사에서 직책이 달라지면 각 직책의 기간을 구분한다. 날짜를 오른쪽에 맞출 때는 문단의 탭 정지를 사용하고, 추출 텍스트에서도 어느 역할의 기간인지 확인한다. 공백 반복으로 정렬하지 않는다.

확인된 성과와 관련 조건을 함께 강조한다. 수치만 큰 타일로 떼어 놓으면 대상·분모·기간이 사라질 수 있다. 팀 성과와 개인 역할의 문장을 함께 유지한다. 겸직은 역할별 실제 기간을 표시하고 주된 재직과 나란히 합산하지 않는다.

한국 테크 기업 사례를 적용할 때에는 [기업별 근거와 적용 범위](korean-tech-cases.md)를 확인한다. 프로젝트의 문제·판단 이유·본인 기여·결과가 서로 가까이 놓이게 하고, 기술명과 수치만 따로 떼어 강조하지 않는다. 이는 해당 사례를 참고한 정보 배치 원칙이며 기업이 지정한 공통 템플릿이 아니다. 내용이 부족하면 확인할 사실을 표시하고, 설득력을 위해 새로운 성과나 선택 이유를 만들어 넣지 않는다.

## 한글·영문 혼용

자유 형식 한글 문서의 기본 서체는 **Pretendard**다(S12). 본문은 Regular 11 pt, 소제목·회사·직책은 SemiBold 11~12 pt, 이름은 Bold 22 pt를 시작값으로 쓴다. 같은 문서의 영문 제품명·숫자도 이 계열로 맞춘다. 별도의 영문 예제는 Noto Sans를 사용한다. 이는 이 프로젝트의 시각적 선택이며 채용 성과가 우수하다는 주장이 아니다.

문서용 정적 OTF/TTF의 Regular·SemiBold·Bold를 실제로 설치한다. 이 예제에서 확인한 정적 OTF는 Pretendard 1.3.9이며, SemiBold의 Word 패밀리 이름은 `Pretendard SemiBold`다. 해당 패밀리에 Bold를 다시 적용해 합성 굵기를 만들지 않는다. 글꼴이 없으면 공식 배포본 설치를 우선하고, 설치가 불가능하면 Noto Sans CJK KR 같은 실제 사용 가능한 대안을 명시한 뒤 다시 렌더한다. 회사 지정 글꼴은 항상 우선한다.

Word의 동아시아 글꼴 속성과 영문 속성을 함께 확인한다(S8). `font.name`만 바뀌었다고 한글까지 적용됐다고 가정하지 않는다.

회사명·제품명·버전의 철자와 대소문자를 유지한다. 긴 이름은 자연스러운 경계에서 줄바꿈한다. 짧은 제품명과 버전은 필요할 때만 함께 묶는다. 긴 URL 전체를 줄바꿈 금지로 만들지 않는다. PDF에서 한글, 영문, 숫자, 괄호를 각각 검색·복사해 확인한다.

글꼴 파일은 이 패키지에 포함하지 않는다. 다른 시스템에서 DOCX를 열면 글꼴 대체로 줄바꿈이 달라질 수 있다. PDF의 글꼴 포함 상태와 실제 표시를 별도로 확인한다.

## 페이지가 짧게 남았을 때

1. 의무 쪽수, 동의·서명 페이지와 일반 내용의 넘침을 구분한다.
2. 수동 페이지·구역 나누기, 빈 문단, `keep_with_next`의 연쇄, 고정 행 높이를 확인한다.
3. 중복·낮은 관련성 내용의 편집이 허용됐다면 먼저 정리하고 사실을 대조한다.
4. 문단·셀 여백을 일관되게 조정한다. 한두 구역만 압축하거나 늘리지 않는다.
5. 제목·회사·직책·기간·첫 설명을 함께 두고 긴 본문은 자연스럽게 나눈다.
6. 그래도 읽기 어렵다면 추가 쪽을 허용하거나 상세 경력기술서 분리를 검토한다. 필수 정보 삭제, 숨김, 작은 글씨로 문제를 감추지 않는다.

## 시각 포트폴리오

작품을 보는 것이 업무 판단에 필요한 경우 포트폴리오에 시각 자료를 배치한다. 이력서와 작품집의 역할은 구분하되 파일을 분리할지 합칠지는 제출처의 안내를 따른다. 채용 이력서에는 읽을 수 있는 텍스트와 역할·기간을 유지하고, 포트폴리오 링크는 제출처가 허용하는 방식으로 제공한다. 파일 제출이 요구되면 링크만으로 대신하지 않는다. 사진·아이콘·숙련도 막대는 정보를 더 정확하게 전달하는 근거가 있을 때만 검토하며, 기본 템플릿에는 넣지 않는다.
